# Step 0: セットアップと「チャット往復」の痛み

このステップでは環境を整え、**あえて非効率なやり方**で Claude Code を使います。
この痛みが、以降のすべてのステップの出発点になります。

## セットアップ

```bash
cd app
npm install
npm test
```

テストが **6件失敗** することを確認してください。これは意図的に仕込まれた欠陥です。
lint も確認します。

```bash
npm run lint
```

**3件のエラー** が出るはずです。アプリの動作も見ておきましょう。

```bash
npm run kakeibo -- summary 2026-07
npm run kakeibo -- budget 2026-07
```

集計額が明らかにおかしい（7月末の支出が抜けている）ことに気づくでしょうか。

## 演習: チャットとして使う

リポジトリルートで Claude Code を起動し、**次のルールで** バグを1つ直してもらいます。

> **ルール: 検証コマンドは自分（人間）だけが実行する。Claude にはコード修正だけをさせる。**

注意: このルールは**プロンプトに明記して Claude 自身に課す**必要があります。
Claude Code は放っておくと自分でテストを実行し、見つけた失敗を全部まとめて
直してしまうからです（実はそれが Step 1 で設計する「検証ループ」そのものです。
Step 0 では旧来の人間主導のやり方を体験するため、あえて封印します）。

こう頼んでください（バグの内容はあえて曖昧に、制約だけ明確に）:

```
予算ぴったりのときの判定がおかしい気がします。そこだけ直してください。
他に気になる箇所があっても、今回はこの1点以外は直さないでください。
テストなどの検証コマンドは私が自分で実行するので、あなたは実行しないでください。
```

Claude が修正したら、**あなたが** `npm test` を実行し、結果をコピーして Claude に貼り付けて次の指示を出します。これを **失敗テストが1件でも減るまで** 繰り返してください。

余裕があれば、残りの失敗テストについても同じ往復を続けてみてください。
5分で「もういい」と思ったら、それが正しい感覚です。

> **もし Claude が制約を無視して全部直してしまったら**、次のコマンドで教材を
> 初期状態に戻してやり直せます（Step 1 の題材がなくなってしまうため）。
>
> ```bash
> git checkout -- app
> ```

## チェックポイント

次の質問に答えてから Step 1 へ進んでください。

1. この演習で、あなたは何回「コマンドを実行して結果を貼り付ける係」をやりましたか？
2. その作業の中で、あなたにしかできない判断は何回ありましたか？
3. Claude は修正能力が足りなかったのでしょうか。それとも**検証手段**を持っていなかったのでしょうか？

> ここで感じた「自分が検証係・伝書鳩になっている」感覚が、ループエンジニアリングが解消する最初の痛みです。
