## コンセプト: Automations はループの心臓

1周分のサイクル（タスク選択→実装→検証→レビュー→記録）が信頼できるなら、
その繰り返しはツールに任せられます。これがループを「ループ」にする最後の部品です。

人間の仕事はループの**外**に移ります: 流れる結果を監視し、おかしな方向に進んだら
止めて軌道修正する。エッセイの言葉でいう**トリアージ役**です。

## 演習: フルループを回す（25分）

`/clear` した新しいセッションで、Claude Code の `/loop` を使います。

```
/loop BACKLOG.md の最優先の未完了タスクを1つ選び、SPEC.md に従って実装する。
app で npm test / npm run lint / npm run typecheck を実行してすべて成功させ、
reviewer サブエージェントのレビューで承認を得る。差し戻されたら修正する。
承認されたら BACKLOG.md に完了を記録し、変更をコミットする。
未完了タスクがなくなったらループを終了する。
```

> **コスト注意**: 残りタスクは3〜4件で、完走まで数十分・相応のトークンを消費します。
> 時間がなければ2周見届けた時点で止めても学習目標は達成できます。
> `/loop` が使えない環境では、同じ内容を「BACKLOG が空になるまで繰り返してください」と
> 依頼しても近い体験ができます。

## 終章: 人間は何をエンジニアリングするのか（10分）

ループは完成しました。最後に、エッセイが警告する3つの問いに答えてください。

1. **検証責任**: ループの全コミット、あなたは中身を説明できますか？
   「テストが通った」と「正しい」の間にある差分を埋めるのは誰ですか？
2. **理解負債（comprehension debt）**: このハンズオンの kakeibo なら全コードを読めます。
   これが10万行の本番コードで、ループが1日20コミット積んだら？
3. **認知的明け渡し（cognitive surrender）**: ループの出力を受け入れるだけの存在に
   ならないために、あなたはループの**どこに**人間の判断を残しますか？

> "Build the loop. But build it like someone who intends to stay the engineer,
> not just the person who presses go." — Addy Osmani

あなたが設計したのは、プロンプトではなく **ゴール（SPEC）・状態（BACKLOG）・
検証（テストと reviewer）・繰り返し（/loop）** という構造でした。
これがループエンジニアリングです。
